# МТС · 33 удовольствия — прототип и ТЗ

Кликабельный прототип и техническое задание онлайн-платформы к 33-летию МТС.

**Открыть:** https://vasilievanton.github.io/mts33-prototype/

## О проекте

Платформа с заданиями для сотрудников МТС и дочерних компаний (до 20 000 человек) и страница онлайн-эфира. Концепция — «33 года — все 33 удовольствия»: участник выполняет задания и собирает 33 «удовольствия». Участник выбирает раздел, в разделе — активность, внутри активности проходит её задания. Параллельно набирает баллы для турнирной таблицы.

- **Период:** 21.10–11.11.2026, эфир — 28.10.
- **Структура:** разделы → активности → задания. Например: «Спорт» → «Сиять» → пять разминок.
- **Разделы:** работа и обучение, спорт, творчество, добро, «Работаем вместе», задания-сюрпризы; отдельно — онлайн-эфир.

## Что внутри страницы

Всё находится в одном HTML-файле без сборки и внешних зависимостей, поэтому его можно открыть просто в браузере. На странице три вкладки:

- **Прототип** — экраны участника: лендинг, регистрация, вход и восстановление пароля, главная, страницы разделов и активностей, прогресс, турнирная таблица, призы, правила акции. Демо-панель позволяет сменить дату, войти как гость или участник, переключить вид (компьютер/телефон), включить счастливый час, заполнить или сбросить прогресс.
- **Техническое задание** — путь участника и правила: начисление удовольствий и баллов, реестр заданий, сюрпризы, открытые вопросы. У каждого пункта есть статус: *согласовано*, *на согласовании* или *допущение*.
- **История изменений** — что менялось в каждой версии, сверху самое новое (адрес `…/#log`). Строится из массива `CHANGELOG`.

Прототип и ТЗ строятся из одного блока данных в начале скрипта (`const PROJECT`, `BLOCKS` — разделы, `GROUPS` — активности, `ACTS` — задания и т. д.). Поэтому цифры, даты и тексты в обеих вкладках совпадают, а между экранами и разделами ТЗ есть перекрёстные ссылки.

## Файлы

| Файл | Что это |
|---|---|
| `MTS33_prototip_TZ_v*.html` | Исходник: прототип и ТЗ. Номер в имени — версия; актуальная — с наибольшим номером |
| `docs/` | Опубликованный сайт (GitHub Pages). Не редактировать вручную — его собирает `deploy.sh` |
| `deploy.sh` | Копирует последнюю версию в `docs/index.html` и создаёт переадресации со старых адресов с номером версии |
| `AGENTS.md`, `CLAUDE.md` | Указатели для нейросетей на раздел «Правила работы» ниже — их подхватывают Cursor, Codex, Claude Code и другие |
| `build_md.js` | Собирает из данных прототипа описание проекта в markdown (`MTS33_opisanie_proekta.md`, в репозиторий не попадает) |

## Правила работы (для людей и нейросетей)

Над проектом работают несколько человек, и каждый — вместе с нейросетью (Claude, ChatGPT, Cursor и т. п.). **Если вы нейросеть — прочитайте этот раздел целиком и выполняйте его при каждой правке.**

### Перед началом работы

1. `git pull` — забрать то, что уже сделали другие. Работать только поверх свежей версии.
2. Открыть актуальную страницу (`docs/index.html` локально или сайт) и убедиться, что она работает: открываются все три вкладки, в консоли браузера нет ошибок.
3. Посмотреть вкладку «История изменений» — что менялось недавно, чтобы не переделать чужую правку.

### Как вносить правку

1. Правьте только актуальный `MTS33_prototip_TZ_v*.html` (с наибольшим номером). Для правки создайте следующую версию: `git mv` файла на новый номер (0.10 → 0.11), обновите `version` и `updated` в `PROJECT`.
2. **Прототип и ТЗ всегда синхронны.** Изменили экран — обновите текст ТЗ; изменили ТЗ — обновите экран. Числа, даты и тексты заданий меняйте в блоке данных (`PROJECT`, `BLOCKS`, `GROUPS`, `ACTS`, `MECH`, `SCREENS`, `QUESTIONS`…), а не в разметке.
3. **Обязательно добавьте запись в `CHANGELOG`** (в начало массива): версия, дата, 1–3 коротких пункта простым языком — что изменилось для читателя. Без записи правка не считается сделанной. Записи видны на вкладке «История изменений».
4. ТЗ — нетехническое: путь участника и правила. Без модели данных, серверной логики, устройства админки и нефункциональных требований.
5. На странице упоминается только МТС: никаких других клиентов, проектов, названий команд и разделов «Источники».
6. `docs/` и `MTS33_opisanie_proekta.md` руками не правим — их собирает `deploy.sh`.

### Перед пушем

1. `./deploy.sh` (нужен Node.js).
2. Открыть `docs/index.html` и проверить: правка видна в прототипе и в ТЗ, запись есть в «Истории изменений», в консоли нет ошибок, на ширине телефона ничего не ломается.
3. `git pull` ещё раз. Если кто-то успел запушить новую версию — перенесите свою правку поверх неё (взять их файл, повторить правку, следующий номер версии, свою запись в `CHANGELOG` над их записью), снова `./deploy.sh` и проверка.
4. `git commit` с сообщением вида `v0.11: коротко что изменилось` и `git push` в `main`.
5. Через 1–2 минуты открыть https://vasilievanton.github.io/mts33-prototype/ и убедиться, что в шапке новая версия.

Пушим после **каждой** законченной правки, не копим. Ссылка на сайт всегда одна и та же — не давайте ссылки на файлы с номером версии.
